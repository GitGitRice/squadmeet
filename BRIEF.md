## Abschlussprojekt – Fullstack, Backend & DevOps

In den nächsten 3 Wochen entwickelt ihr in Teams von 3–5 Personen (ggf. auch Einzelprojekte)
eine eigene praxisnahe Anwendung.

### Ziel

Entwickelt eine Lösung für ein reales Problem und verbindet dabei möglichst viel von dem, was
ihr im Kurs gelernt habt.

### Mögliche Themen (Beispiele zur Themenfindung)

- IT-Service / Helpdesk
- Asset- & Lizenzmanagement
- Onboarding / Offboarding
- Inventar / Lager
- Buchungs- & Verwaltungssysteme
- Monitoring / Reporting
- Kurs- / Teilnehmerverwaltung
- oder natürlich eure eigene Idee

### Technologie

Ihr habt freie Technologiewahl.
React, FastAPI, PostgreSQL, Docker, GitHub Actions, AWS, Terraform, Ansible usw. sind Beispiele.

Entscheidend ist nicht, wie viele Tools ihr auf das Projekt klebt, sondern ob ihr sinnvoll
erklären könnt, warum ihr sie verwendet.

### Grunderwartungen

- **Cloud Deployment** — Die Anwendung wird in einer Cloud-Umgebung deployt und lauffähig
  bereitgestellt.
- **Docker** — Der zentrale Anwendungsbestandteil wird containerisiert.
- **CI/CD** — Eine automatisierte Pipeline für Test → Build → Deployment gehört zum Projekt.
  GitHub Actions ist möglich, aber nicht vorgeschrieben.

### Ablauf – 3 Sprints (je 1 Woche)

- **Woche 1 – Planung & MVP:** Idee → Architektur → Git → Aufgaben → erste funktionierende Version
- **Woche 2 – Entwicklung & Integration:** Features → Frontend/Backend → Datenbank → Docker →
  CI/CD → Cloud
- **Woche 3 – Stabilisierung & Präsentation:** Fehler beheben → testen → dokumentieren →
  Deployment finalisieren → Präsentation vorbereiten

### Präsentation

15–20 Minuten pro Team, inklusive Live-Demo. Zeigt dabei:

- Problem & Lösung
- Architektur
- Technologien
- wichtige Funktionen
- technische Herausforderungen
- Cloud Deployment
- Docker
- CI/CD
- Lessons Learned

### Weitere Erwartungen

- sinnvoller realer Use Case
- mindestens ein vollständiger Business-Workflow
- Git/GitHub & regelmäßige Commits
- grundlegende Tests
- sinnvolle Dokumentation
- mindestens ein interessanter Debugging-Fall

### Bonus

Wer die Grunderwartungen bereits sauber umgesetzt hat, kann noch eine Schippe drauflegen:

- Terraform / Infrastructure as Code
- Ansible / Configuration Management
- Advanced Security & Secrets
- HTTPS / Reverse Proxy / eigene Domain
- Monitoring & Observability
- umfangreiche automatisierte Tests
- Skalierung & Performance
- Backup & Recovery
- Monitoring & Alerting
- Rollback-Strategien
- vollständige End-to-End-Automatisierung

### Kurz gesagt

Cloud + Docker + CI/CD sind die Basis. Alles darüber hinaus ist eure Spielwiese.

Und bitte denkt daran: Ein Projekt wird nicht automatisch besser, nur weil im README 23 Logos
stehen. Build something useful. Automate what makes sense. Understand what you build.
